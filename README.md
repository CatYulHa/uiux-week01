## UI/UX 프로그래밍 · 1주차

- 주제: UI/UX 프로그래밍의 이해와 웹 인터페이스의 기본 구조

### 구성

- `index.html`: UI와 UX 설명, 좋은 경험의 5원칙, 웹 기술 소개, 인터랙션 실습
- `style.css`: 녹색 계열 디자인, 모바일 반응형 레이아웃, 키보드 포커스 표시
- `script.js`: 기술 소개 탭 전환, 키보드 탐색, 클릭 카운터와 초기화


## 2주차 UX 기획

- 사용자: UI와 UX, 웹의 기본 구조를 처음 배움
- 목적: 서비스의 학습 내용과 이용 방법을 이해하고 첫 웹 학습
- 행동: 페이지 안에서 필요한 정보를 찾고, 오늘의 학습 목표를 입력한 뒤 학습실을 이용
- 순서: 서비스 이름과 한 줄 소개 → 서비스 소개 → 주요 기능 3개 → 이용 방법 3단계 → 학습 목표 입력 → 하단 정보.


## 3주차 CSS 변경

- 변경: 과제 소개와 실습 내용 카드에 `display: flex`와 `gap`을 적용했습니다.
- 이유: 세 가지 실습을 같은 그룹으로 묶고, 글과 이미지를 나란히 비교하기 쉽게 하기 위해서입니다.

- 변경: 메뉴, 학습 목표 입력창, 버튼에 hover·focus·active 상태와 transition을 추가했습니다.
- 이유: 현재 조작 위치와 클릭 결과를 확인하고 상태 변화를 자연스럽게 연결하기 위해서입니다.

## 4주차 반응형 수정

- 확인한 문제: 390px에서 메뉴가 한 줄로 남아 링크 사이가 좁았고, 1100px에서 769px로 줄이면 실습 내용 카드 세 개가 한 줄에 눌려 문장이 자주 끊겼습니다. 모바일 규칙도 720px로 되어 있어 721~768px에서는 데스크톱 배치가 그대로 남았습니다.

- 변경: `index.html`의 viewport 메타 태그(`width=device-width, initial-scale=1.0`)를 확인했습니다. 1주차부터 있었기 때문에 중복해서 추가하지 않았습니다.
- 이유: 모바일 브라우저가 실제 화면 너비를 CSS 기준으로 사용해야 768px 미디어 쿼리가 예상한 시점에 적용되기 때문입니다.

- 변경: 콘텐츠 영역 `.wrap`에 `width: calc(100% - 64px)`와 `max-width: 1120px`를, 서비스 화면 이미지에 `width: 100%`와 `max-width: 100%`를 적용했습니다.
- 이유: 좁은 화면에서는 콘텐츠와 이미지가 함께 줄어들고, 넓은 화면에서는 일정 너비에서 멈춰 글이 지나치게 길어지지 않게 하기 위해서입니다.

- 변경: 실습 내용 카드 목록 `.feature-grid`를 Flexbox에서 Grid(`repeat(auto-fit, minmax(260px, 1fr))`)로 바꾸고 카드에 `min-width: 0`을 추가했습니다.
- 이유: 화면 너비에 따라 3열 → 2열 → 1열로 열 수를 자동으로 조정해 카드가 눌리지 않게 하기 위해서입니다.

- 변경: 학습 목표 입력창과 버튼을 넓은 화면에서는 한 줄에 놓고, 자리가 부족하면 `flex-wrap`으로 다음 줄에 배치했습니다.
- 이유: 넓은 화면에서는 입력과 제출을 한눈에 보고, 좁은 화면에서는 입력창이 버튼에 너비를 빼앗기지 않게 하기 위해서입니다.

- 변경: `style.css` 맨 아래에 `@media (max-width: 768px)`를 하나만 작성하고, 1~3주차의 720px 모바일 규칙도 이 안으로 옮겼습니다.
  - 메뉴를 세로로 배치하고 링크 주변 여백을 늘렸습니다.
  - 실습 내용 카드를 `grid-template-columns: 1fr`로 한 열에 배치했습니다.
  - 학습 목표 입력창과 버튼을 세로로 배치하고, 버튼 높이를 48px 이상으로 정했습니다.
  - 제목을 32px로 줄이고, 카드·실습 순서·하단 정보의 작은 글자를 키우고 세로 여백을 줄였습니다.
- 이유: 전환 기준을 768px 하나로 통일해 769px에서는 기본 규칙, 768px부터는 모바일 규칙이 적용되도록 하기 위해서입니다.

- 달라진 점: 1100px에서는 메뉴·카드·입력 폼이 가로로 보이고, 769px에서는 카드가 2열로 바뀌며, 768px과 390px에서는 메뉴·카드·입력 폼이 한 열로 바뀝니다. 네 화면 모두 가로 스크롤 없이 내용이 잘리거나 겹치지 않는 것을 개발자 도구와 320px 화면에서 확인했습니다.
