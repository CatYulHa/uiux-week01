## 9주차 학습 기록 폼

- 추가: 학습 기록 폼(`#record`), 메뉴 `학습 기록`, 계획 완료 화면의 `학습 기록 남기기` 링크 추가함
- 저장: localStorage에 저장하고 `저장한 기록`에 최근 5개 표시함
- 조건부 입력: `헷갈린 부분이 있어요` 체크 시 `헷갈린 부분` 칸 표시, 해제 시 숨기고 `disabled` 처리함
- 입력 중: 글자 수와 조건 충족 여부를 문구와 색으로 표시함
- 제출: `submit`에서 검사, 오류가 있으면 저장을 막고 첫 오류 칸으로 초점 이동함
- 저장 중: `저장 중…` 표시, 버튼 `disabled`로 중복 제출 막음
- 완료·실패: 완료 시 목록에 새 기록 추가, 실패 시 입력값 유지하고 `다시 저장하기`로 재시도함
- 다시 작성: 입력값, 문구, 버튼 상태 초기화함

### 입력 조건

| 항목 | 종류 | 조건 | 오류 문구 |
| --- | --- | --- | --- |
| 실습한 예제 | select | 필수 | `실습한 예제를 골라 주세요.` |
| 오늘 배운 점 | textarea | 필수, 공백 제외 10–200자 | `오늘 배운 점을 입력해 주세요.` / `오늘 배운 점을 10자 이상 적어 주세요.` |
| 헷갈린 부분 | textarea | 체크 시 필수, 5–100자 | `헷갈린 부분을 입력해 주세요.` / `헷갈린 부분을 5자 이상 적어 주세요.` |

### 실패 처리

- 조건: 사이트 데이터 차단, 저장 공간 부족 등으로 localStorage에 쓸 수 없을 때
- 코드: `script.js`의 `saveRecord()`에서 `try`·`catch`로 처리, `finishRecordSave()`에서 실패 문구 표시

### 확인 순서

배포 주소에서 1100px, 768px, 390px로 확인

1. 빈 값 제출: 두 칸에 오류 표시, 저장 안 됨
2. 잘못된 값: 배운 점 4자 입력 시 `오늘 배운 점을 10자 이상 적어 주세요.`
3. 오류 수정: 10자 이상 입력 시 오류 해제, `입력 조건을 충족했습니다.`
4. 조건부 영역: 체크 시 칸 표시, 해제 시 숨김·`disabled`
5. 정상 제출: `저장 중…` 후 목록에 추가, 새로고침해도 유지
6. 실패: 저장소를 막고 저장 시 입력값 유지, `다시 저장하기`로 재시도
7. 다시 작성: 입력값, 문구, 버튼 초기화
8. 모바일(390px): 가로 스크롤·잘림 없음, 터치로 저장까지 조작

## 중간고사 추가 기능

7주차 학습 계획 완료 뒤에 고른 예제의 이해도 확인 퀴즈(3문제)를 추가함. 채점하면 문제마다 정답·오답과 힌트를 표시하고, 틀린 문제만 다시 풀 수 있음.

- 연결 지점: 7주차 흐름의 끝(계획 완료 화면)에 `이해도 퀴즈 풀기` 버튼 추가
- 반영 값: 계획에서 고른 예제에 맞는 문제 3개, 계획의 학습 목표(`목표: …`)
- 흐름: 계획 완료 → `이해도 퀴즈 풀기` → 답 고르기 → `채점하기` → (오답) `틀린 문제 다시 풀기` → `✓ 퀴즈 통과`

| 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기 반응 | 다음 행동 |
| --- | --- | --- | --- | --- |
| `이해도 퀴즈 풀기` 클릭 | 계획에서 고른 예제 | 그 예제의 문제 3개, 목표, `0 / 3문제 답함` 표시 | 없음 | 답 고르기 |
| 답 고르기 | 문제마다 하나 | `N / 3문제 답함`, 고른 보기 강조 | 오류 표시된 문제를 고르면 그 문제의 오류만 지움 | `채점하기` |
| `채점하기` 클릭 | 3문제 모두 답했는지 | 채점 진행 | 오류: `1번, 2번, 3번 문제의 답을 골라 주세요.`처럼 번호 안내, 빨간 테두리, 첫 빈 문제로 초점 | 빈 문제 고르기 |
| `채점하기` 클릭 | 정답과 같은지 | 모두 맞힘: `✓ 퀴즈 통과`, `채점 N번`, 초록 상자 | 틀림: `3문제 중 N개 정답`, 틀린 문제에 `오답입니다. 힌트: …`, 답 잠금 | 통과: 예제 다시 보기 / 틀림: `틀린 문제 다시 풀기` |
| `틀린 문제 다시 풀기` 클릭 | 틀린 문제 | 틀린 문제만 답을 지우고 `힌트: …` 유지, 맞힌 문제는 잠금 유지 | 없음 | 다시 `채점하기` |
| `계획 보기` 클릭 | 없음 | 완료 화면으로 이동, 답·결과 유지, 버튼이 `퀴즈 이어서 풀기`로 바뀜 | 통과 뒤에는 `퀴즈 결과 보기`, `퀴즈 통과 · 채점 N번` | 퀴즈로 돌아가기 |
| `그만두기` 클릭 | 고른 답이 있는지 | 없음: 바로 닫고 `퀴즈를 그만뒀습니다. 언제든 다시 풀 수 있습니다.` | 있음: `그만두면 고른 답과 채점 결과가 지워집니다.` 확인 → `계속 풀기`는 답 유지, `그만두기`는 초기화 | `이해도 퀴즈 풀기` |
| `다시 세우기` 클릭 | 없음 | 계획과 함께 퀴즈 답·결과·횟수 초기화 | 없음 | 새 계획, 새 예제의 퀴즈 |

## 중간고사 테스트 결과

배포 주소(https://catyulha.github.io/uiux-week01/)에서 1100px, 768px, 390px로 확인

- 정상: 계획 완료 → 퀴즈 → 모두 정답 → `✓ 퀴즈 통과`, `UI와 UX 비교하기 다시 보기`로 예제 탭 열림
- 반영: 고른 예제(개념·코드·클릭)마다 다른 문제 표시, 목표 문구 표시, 다시 세우기 뒤 새 예제 문제로 바뀜
- 오류: 답 없이 채점하면 `1번, 2번, 3번 문제의 답을 골라 주세요.`, 하나 고를 때마다 남은 번호만 안내
- 오답: 2개 틀리면 `3문제 중 1개 정답`과 힌트 표시, 채점한 답은 바꿀 수 없음
- 다시 풀기: 틀린 문제만 비워짐, 다시 틀리면 다시 풀기 반복, 세 번째 채점에서 통과하면 `채점 3번`
- 이전: `계획 보기` 후 돌아와도 고른 답과 결과 유지, 완료 화면에 `퀴즈 2 / 3문제 답함` 표시
- 취소: 답이 없으면 바로 닫힘, 답이 있으면 확인 상자 표시, `계속 풀기`는 답 유지, `그만두기`는 답 초기화
- 키보드: Tab, Space, 방향키로 답 고르기, Enter로 채점
- 모바일(390px): 터치로 전체 경로 조작, 가로 스크롤과 잘림 없음, 버튼·보기 높이 44px 이상
- 기존 기능: 7주차 학습 계획, 탭, 글자 수, 실습 순서 체크 동작

## 사용자 흐름 (7주차)

시작 → 1 목표 입력 → 2 예제·시간 선택 → 3 계획 확인 → 완료

- 시작: `학습 계획 세우기` 버튼
- 1 목표 입력: 목표(필수, 5–80자) 입력 → `학습 목표 정하기` → `다음 · 예제 고르기`
- 2 예제·시간 선택: 예제(필수, 3개 중 1개), 시간(10·20·30분) → `다음 · 계획 확인`
- 3 계획 확인: 목표·예제·시간 확인 → `계획 확정`, 수정은 `이전`
- 완료: `계획 완료` 표시, 고른 예제로 이동, `다시 세우기`

## 3주차 CSS 변경

- 변경: 과제 소개와 실습 내용 카드에 `display: flex`와 `gap`을 적용했습니다.
- 이유: 세 가지 실습을 같은 그룹으로 묶고, 글과 이미지를 나란히 비교하기 쉽게 하기 위해서입니다.

- 변경: 메뉴, 학습 목표 입력창, 버튼에 hover·focus·active 상태와 transition을 추가했습니다.
- 이유: 현재 조작 위치와 클릭 결과를 확인하고 상태 변화를 자연스럽게 연결하기 위해서입니다.


## 4주차 반응형 CSS

- viewport: `width=device-width, initial-scale=1.0` 메타 태그 사용
- 유동 너비: 콘텐츠 영역 `width: calc(100% - 64px)`, `max-width: 1120px` / 이미지 `width: 100%`, `max-width: 100%`
- Grid: 실습 내용 카드를 `repeat(auto-fit, minmax(260px, 1fr))`로 배치
- `@media (max-width: 768px)`: 메뉴 세로 배치, 카드 한 열, 입력창과 버튼 세로 배치, 글자 크기와 여백 조정
- 확인: 1100px, 768px, 390px에서 가로 스크롤과 잘림 없음


## 5주차 JavaScript

- 연결: `</body>` 앞에서 `script.js`, `learning.js` 불러오기
- 요소 선택: `querySelector`로 학습 목표 폼·입력창·버튼·결과 문구 선택
- 함수·이벤트: `submit`에 `handleGoalSubmit`, `input`에 `handleGoalInput` 연결 / `event.preventDefault()`로 새로고침 방지
- 변수·조건문: `const minGoalLength = 5`, `let savedGoal = ''` / `if`·`else`로 빈 입력, 5자 미만, 처음 정한 목표, 바꾼 목표 구분
- 피드백: `textContent`로 안내 문구, `classList`로 `is-success`·`is-error` 색, `disabled`로 버튼 완료 상태 표시
- 확인: 1100px, 768px, 390px에서 입력·제출·버튼 상태 변화 확인


## 6주차 이벤트와 탭 UI

- click: 실습 내용 탭 3개 전환 / `오늘 학습 마치기` 버튼 → 완료 문구·완료 배경색·버튼 `disabled`
- input: 학습 목표 입력 → 글자 수 `N / 80자` 문구 갱신, 5자 이상이면 `is-ready` 초록색
- change: 실습 순서 체크박스 → `N / 3단계 완료` 문구·진행 막대·단계 ✓ 표시, 세 단계를 모두 체크하면 마치기 버튼 활성화
- 탭: `querySelectorAll`·`forEach`로 탭 3개에 click 연결, 선택한 탭만 `is-active`·`aria-selected="true"`, `data-target` 패널만 표시 / 방향키·Home·End 이동
- 테스트 결과 (1100px·768px·390px, 모두 통과)
  - 탭: 3개 모두 전환, 선택한 탭과 패널이 1개씩만 표시, 768px 이하에서 세로 배치
  - input: 입력·삭제할 때 글자 수 0–80 즉시 일치, 80자 넘는 입력 막힘
  - change·click: 체크·해제할 때 문구·막대·버튼 상태가 함께 바뀜, 마치기 후 버튼 비활성화
  - 키보드: Tab·Enter·Space·방향키로 탭·체크박스·버튼 조작
  - 화면: 가로 스크롤과 잘림 없음


## 7주차 사용자 흐름

- 단계: `.plan-step`(`data-step` 0–4) 중 `showPlanStep()`이 현재 단계만 표시
- 진입: `#plan-start`, `data-plan-start` 링크 → 1단계(5주차 학습 목표 폼)
- 검사: `getGoalError()`, `handlePlanCheck()`에서 필수값이 없으면 현재 단계 유지, 오류 문구 표시
- 확인 화면: `fillPlanSummary()`가 목표·예제·시간을 `[data-summary]`에 표시
- 이전·다시 세우기: `goToPlanStep()`은 값 유지, `resetPlan()`은 초기화
- 확인: 1100px, 768px, 390px에서 정상·오류·이전·다시 세우기 확인


## 8주차 중간고사 이해도 퀴즈

- 연결: 계획 완료 화면의 `#plan-quiz` → `openQuiz()`가 고른 예제의 `.quiz-set`만 표시
- 검사: `handleQuizSubmit()`에서 답하지 않은 문제 번호 안내, `gradeQuiz()`가 `quizAnswers`와 비교
- 상태: `quizState`(solving·retry·passed)에 따라 버튼과 결과 상자 변경, `data-state`로 색 표시
- 다시 풀기: `handleQuizRetry()`가 틀린 문제만 비우고 힌트 유지
- 이전·취소: `closeQuiz()`는 답 유지, `handleQuizStop()`은 확인 후 `resetQuiz()`
- 확인: 1100px, 768px, 390px에서 정상·오류·오답·다시 풀기·이전·취소 확인


## 9주차 폼 UI와 입력 경험

- 구조: `label for`·`id`, `name`, `aria-describedby`로 안내·오류 연결, `novalidate`
